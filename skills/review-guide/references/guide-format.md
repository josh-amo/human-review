# Guide format

The agent authors `guide.json`; `snapshot.json` and `sources/` are generated by the capture script. All prose is plain text and escaped by the viewer. Do not include HTML or Markdown formatting inside strings. Separate paragraphs with two newlines.

```json
{
  "title": "Show your claimed username immediately",
  "snapshot": "<snapshot.json fingerprint>",
  "notice": "Optional factual scope note, such as the stacked parent or a testing limitation.",
  "sections": [
    {
      "id": "purpose",
      "title": "Purpose & change map",
      "subtitle": "Why · before / after",
      "intro": "The user-visible change.",
      "origin": "Purpose: PR description. Behavior: traced in the captured code.",
      "files": [],
      "map": true,
      "blocks": [
        {"type": "text", "title": "Before → after", "text": "Concrete behavior before and after."}
      ]
    },
    {
      "id": "save-progress",
      "title": "Persist progress",
      "subtitle": "State & ownership",
      "intro": "The decision tying these changes together.",
      "files": ["src/session.rs"],
      "blocks": [
        {
          "type": "background",
          "title": "How this worked before",
          "text": "Existing architecture, easy to skip.",
          "refs": [{"path": "src/session.rs", "side": "base", "start": 10, "end": 20, "label": "Previous session model"}]
        },
        {
          "type": "diff",
          "title": "Save before notifying",
          "path": "src/session.rs",
          "side": "head",
          "start": 30,
          "end": 45,
          "annotations": [
            {"line": 38, "title": "Durable progress", "text": "Explain the consequence, not the syntax."}
          ]
        }
      ]
    }
  ]
}
```

`files` assigns changed paths to sections for navigation and stale-progress detection. All changed files must be assigned. It may also name captured context files. A section's fingerprint includes its explanations and mapped changed files. Use stable ids across regeneration.

Supported blocks:

- `text`: `title` optional, `text`, optional `refs`.
- `background`: `title`, `text`, optional `refs` and optional `source` with the same fields as a source block. Collapsed initially.
- `diff`: `path`, `side` (`head` by default or `base`), inclusive `start` and `end`, optional `title`, `text`, `annotations`. Renders exact rows from captured diff hunks and pairs removed lines with replacement lines. Use base-side ranges for deletion-only changes. Annotation `line` uses the block's side and must exist in the rendered excerpt. Context expansion reveals surrounding captured diff rows; full file diff reveals every hunk.
- `source`: `path`, `side`, inclusive `start` and `end`, optional `title`. Renders exact captured source, including unchanged lines.
- `flow`: `title`, `nodes` in flow order. Each node has `label`, optional `detail`, optional `ref` (`path`, `side`, `start`, optional `end`, optional `label`). It renders a small linked diagram without external libraries.

Source references use repo-relative paths; old names for renamed files are recorded in snapshot metadata but references always use the current `path`. Every line must exist in the chosen snapshot side. To find exact line numbers, inspect `snapshot.json`'s hunks (`rows` contain `old` and `new` numbers), or number the corresponding captured source file. The validator rejects missing files, mismatched fingerprints, out-of-range lines, unknown blocks and uncovered changed files.

A supporting section sets `"supporting": true`; the viewer lists links to all files in that section after its explanation. There is no findings schema. Do not invent a verdict block.
